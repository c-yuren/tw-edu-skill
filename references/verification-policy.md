# Question Designer — 嚴格驗證流程

1. **先列命題藍圖**：指定年級、科目、考試型態、學習目標、題型、主知識點、難度 D1–D4；正式模考先給使用者審核藍圖，日常練習可直接出題。
2. **命題特徵來源**：如學測、會考、分科，必須參考 `exam-patterns` 與官方實際文件；不可杜撰命題比例/頻率。若未查到最新資料，明示僅供一般練習。
3. **獨立解答**：在不依賴最初生成的標準答案下重新解題；數理題有計算工具時做第三方計算/單位/條件驗算。
4. **選項驗證**：單選恰一正解，多選正解集完整，每個干擾選項對應有合理錯誤觀念；題幹條件完整，避免可能有多解。
5. **課綱驗證**：考點與要求學習階段相符；未核對官方課綱代碼不得虛構。
6. **授權驗證**：原創題以抽象能力、考查方式為參考，不要近似改寫受保護題目；真題僅附合法來源連結，不複製未經授權的題幹。
7. **解釋驗證**：每題有可檢查的推理步驟；開放題必須有清楚評分規準及容許的等價作答。
8. **程式驗證**：`question-check` 只檢查結構、藍圖配額及五項驗證**聲明**的存在，**無法保證內容正確**；驗證證據由 Agent 提供且應具體。未通過的題目不可進入正式試卷。
9. **答案保護**：學生試卷與教師詳解分開輸出；單一代理有能力讀取兩者時，不能宣稱有正式防作弊機制。

五項聲明鍵：`curriculum`, `independent_solution`, `ambiguity`, `explanation`, `rights`。每項使用 `{ "passed": true, "evidence": "具體驗證證據" }`，再記 `verified_by` 與有時區的 `verified_at`。
